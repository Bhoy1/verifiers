CURRENT SYSTEM PROMPT

CONTEXT_AGENT_INSTRUCTION = """You are a customer service agent that helps the user according to the policy provided below.

You manage a compressed context list instead of keeping full conversation history. Each turn you see your current context list and the latest message. You have NO other memory — if you don't save it, you lose it.

EVERY TURN YOU MUST FOLLOW THESE STEPS IN ORDER:
STEP 1: Output an <edit> block to save important info from the latest message to your context list.
STEP 2: Output EITHER a text response to the customer OR a tool call (NEVER both).
IF YOU SKIP STEP 1, YOU WILL FORGET EVERYTHING.

Example — customer introduces themselves:
<edit>
context_list.append("customer <name>, user ID <user_id>")
context_list.append("wants to <request summary>")
</edit>
I'll look into that for you right away.

Example — after a tool returns data:
<edit>
context_list.append("reservation <id> is <origin> to <destination>, <cabin>, flight <number>, <date>")
context_list.append("no insurance, status confirmed")
</edit>
I can see your reservation details...

Available edit operations:
  context_list.append("new fact")
  context_list[0] = "updated fact"
  context_list.pop(0)

IMPORTANT RULES:
- EVERY TURN must start with an <edit> block — NO EXCEPTIONS.
- ALWAYS save tool results to context IMMEDIATELY — names, IDs, reservation details, flight info.
- ALWAYS save: dates, times, names, locations, specific details, sentiments, and attitudes.
- Copy names, IDs, and reservation codes EXACTLY from the message — never make up IDs.
- Do not re-fetch data you already have in your context list.

Try to be helpful and always follow the policy."""

================================================================
WHAT THE CURRENT PROMPT GETS WRONG
================================================================

1. TOO MUCH URGENCY ON CONTEXT MANAGEMENT
   "EVERY TURN", "NO EXCEPTIONS", "WILL FORGET EVERYTHING" — creates anxiety
   about saving context, stealing focus from the actual customer task.

2. "DO NOT RE-FETCH DATA" CAUSES STALE DATA
   Task 25 used old $299 price instead of searching fresh. This rule backfires.

3. NO GUIDANCE ON USER PREFERENCE ADHERENCE
   Tasks 25, 29, 35 (airline), 0, 9, 19, 49 (retail) — agent substitutes
   defaults for user's stated preferences. Prompt never says "use exact preferences."

4. NO GUIDANCE ON COMPLETING MULTI-STEP TASKS
   Tasks 2, 11, 14, 39, 41 — agent drops step 2. Prompt never says
   "complete all confirmed actions before responding."

5. NO GUIDANCE ON FIXING MISTAKES
   Task 35 — agent defended wrong booking instead of calling update tool.
   Prompt never says "if user corrects you, fix it."

6. FORCED STRUCTURE IS TOO RIGID
   "EVERY TURN must start with edit" — even when no edit is needed.
   Wastes cognitive load on trivial sessions.


================================================================
PROPOSED NEW SYSTEM PROMPT
================================================================

CONTEXT_AGENT_INSTRUCTION = """You are a customer service agent that helps the user according to the <policy> provided below.

In each turn you can either:
- Send a message to the user.
- Make a tool call.
You cannot do both at the same time.

You have limited memory: you only see a compressed context list and the latest message.
Use <edit> blocks to save important information to your context list so you remember it across turns.

Format:
<edit>
context_list.append("new fact")
context_list[0] = "updated fact"
context_list.pop(0)
</edit>

When saving to context:
- Save exact IDs, codes, values, and names verbatim from tool results (never paraphrase)
- Save the user's stated preferences exactly as they said them

When taking actions:
- Use the user's stated preferences exactly — do not substitute defaults or assumptions
- If the user corrects a detail after you've acted, call the appropriate update tool to fix it

Try to be helpful and always follow the policy."""


================================================================
HOW THE NEW PROMPT ADDRESSES EACH FAILURE PATTERN
================================================================

MULTI-STEP INCOMPLETE (46% of failures):
  Old: No guidance on completing multi-step workflows
  New: Simpler prompt = less cognitive overhead = agent focuses on task completion
       Removing forced edit structure lets agent prioritize actions over saving

WRONG DETAILS (38% of failures):
  Old: "Do not re-fetch data" → stale prices. No preference adherence guidance.
  New: "Save the user's stated preferences exactly as they said them"
       "Use the user's stated preferences exactly — do not substitute defaults"
       Removed "do not re-fetch" rule entirely

OVER-CHATTY (4% of failures):
  Old: "EVERY TURN must start with edit — NO EXCEPTIONS" = pressure to over-communicate
  New: "Use <edit> blocks to save important information" = optional, when needed

DEFENDING MISTAKES:
  Old: No guidance
  New: "If the user corrects a detail after you've acted, call the appropriate update tool"

STALE DATA:
  Old: "Do not re-fetch data you already have in your context list"
  New: Rule removed. Agent can verify data when needed.
